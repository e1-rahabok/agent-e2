## 1. Verdict
- The design is sound and the code matches it where it is built. Code plans what the model reads, computes, asks and checks; the model reads and writes. The model calls no tool.
- Three gaps between the design and the build matter for 1.0:
  1. Stage 3 (compute) runs the catalog and the summation conversion only. The flow executor (`flows.py`) and the planning calculator (`capacity.py`) are built and tested but not called by the agent. Guided troubleshooting is a 1.0 requirement (MISSION.md, Ways to ask, 4), so Q166 blocks it. Q166 now proposes the first flow (`vm-cpu-contention-high`, not VM slow), a step format and a rule for a missing value.
  2. The open-answer shape of Q199 option A is in the prompt (`agent.OPEN_SHAPE`: "Not settled by the knowledge base:"), ahead of the author's answer, and the judge has no rule for that line: its rubric scores "cannot be settled" as 0 and caps at 0 on any contradicting statement. The next round would score it by chance. Q199 now proposes the judge rule (E) whatever option is chosen.
  3. The mission and the gate disagree on the frontier model: the plan's 1.0 minimum says "higher score than frontier models"; the decision of 2026-11-13 made the gap an outcome. New Q212 (recommended: not significantly below the frontier reference as the gate; a win claimed only when the paired test shows it).
- Retrieval is the largest measured gap: BM25 recall 77%, 111 of 196 questions complete, main file missing on 24, against release levels of 95%, 90% and 0. The levers in plan M3 stand (the model's case in the retrieval check, the knowledge links of AGENT.md section 6).
- The documents were mostly current; the errors were leftovers of the tool-loop generation and claims the code does not support.

## 5. Knowledge base
Fixed after a source check (examples; the commit lists the rest):
- vSphere 9.1 and VCF 9.x behaviour: Storage DRS balances space only (Storage I/O Control components deprecated from VCF 9.0); SIOC keeps only IOPS limits (Broadcom KB 385396); a compute vMotion creates no delta disk; virtual-mode RDMs support snapshots; vSAN is its own datastore type, ESA has no cache tier or disk groups; software MMU (shadow page tables) is gone; the ESXi CPU Usage cap ended in vSphere 8.0 Update 3 (KB 417702); 96 hosts per cluster; CPU Hot Add deactivates vNUMA when enabled, and `numa.allowHotadd` keeps it on hardware 20 (KB 313375); a tiered VM's reservation can be served from NVMe; zero pages cost no RAM only once shared; real-time charts ignore the statistics level.
- Mechanisms: the Linux balloon driver is the upstream `vmw_balloon`, not open-vm-tools (KB 313773); Linux steal time needs the VM's steal clock (KB 434983); `rx_dropped` leaves out the VMXNET3 ring-full count (`pkts rx OOB`); an IOPS limit shows as kernel queue time (QAVG, KB 426790); the scheduler spreads vCPUs across cores before pairing threads (vSphere 9.1 documentation); Overlap is subtracted from Used, System added; a halted vCPU is de-scheduled; minFree tiers (about 900 MB for the first 28 GB, then 1%); Mem.CtlMaxPercent 65%; the host TCP retransmit rate exists for VMkernel traffic; TEAM-PNIC; Windows page file, priorities and counter sums; DRS Score as execution efficiency.
- Contradictions between files, arithmetic (units, percentiles, shares per MB, page sizes) and stale names (Aria Operations 8.18; pillars security and value).
- Who-said-it: 47 lines in knowledge text ("the book", "(book)", names); doubts moved to `review_notes` in 9 files.
- Catalog: the host `mem.usage` row pointed at the VM Usage file.
- Retrieval check, BM25, before and after the knowledge fixes: recall 77% both; complete 110 to 111 of 196; main file missing 25 to 24. Gained 0022, 0293 and the main file of 0188; lost the main file of 0213 and one file of 0236.
