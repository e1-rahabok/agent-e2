Quick answer · host esx-21
ESXi host esx-21, 768 GB, no memory tiering. vCenter, past day: memory State High in every sample and Balloon 0 all day. But Swap consumed is flat at 3.1 GB and Compressed flat at 1.2 GB. Swap in, Swap out, Compression and Decompression rates are 0 in every sample. Ballooning comes before swapping, so how can anything be swapped on this host? Is a counter wrong, and do I need to move VMs off it?
Agent E2

Conclusion: the counters are consistent and the host is not under current memory pressure. No VM move is required now; check per-VM memory waits, not an ESXi average.

Mechanism and reason

  • ESXi Memory State High in every sample means free memory is well above Soft/Hard thresholds, so ESXi is not reclaiming now. State is a leading capacity warning, not a wait metric.
  • Host ballooned, compressed and swapped memory are past reclamation, not current pressure. On ESXi one of them can be 0 while the others are not because reclaim order depends on memory state and per-VM settings. vsphere/technology/memory/metrics/comparisons/host-memory-metrics
  • Swap Consumed / ESXi Memory Compressed is what sits in swap / in the compression cache now. It can stay flat for a long time when nothing is touched. Swap In/Out, Compression/Decompression rates are 0, so no pages are moving now.
  • Swapped is past; a VM waits only when pages are read back. Swap-in rate and VM Memory Latency are the wait indicators. ESXi Memory Latency is a normalized average of VM Memory Latency and hides the VM that suffers; it has no relevance for alerting or troubleshooting. Use the maximum VM Memory Contention across the host’s VMs instead.

What to check next

  • Per-VM VM Memory Latency and swap-in rate / decompression rate. Latency is the memory wait; ballooned, swapped and compressed are past reclamation.
  • Per-VM limits / resource pool limits and Balloon Target, and the worst VM Memory Contention on the host.
  • Real-time 20-second samples for the host and VMs to confirm rates stay zero.
