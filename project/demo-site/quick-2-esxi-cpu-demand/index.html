Quick answer · host esx-07
Host esx-07 is quiet: 9 VMs, ESXi CPU Usage about 15% all week. In VCF Operations its ESXi CPU Demand is flat at about 38%. In vCenter the same host shows CPU Demand about 11%, below Usage. My manager reads the VCF Operations gap as unmet demand and asks for another host in the cluster. Is that right? Why do the two tools show different Demand for the same host?
Agent E2

No. The gap is not unmet demand and the host does not need another host. The host is quiet: ESXi CPU Usage ≈15% all week shows low busy time per core. Capacity headroom is read in ESXi Thread/Core Utilization and VM contention, not in Demand.

Why the numbers differ:

ESXi CPU Demand is a sum-of-consumers metric. Same name, two formulas.

  • vCenter cpu.demand is the administration view: sum of the running VMs’ scheduler demand only. It excludes VM CPU reservations and the kernel’s System Resource Reservation. Kernel work is in Usage, not in Demand, so on a quiet host vCenter Demand can sit below Usage.
  • VCF Operations CPU|Demand is the operations/capacity view. Per running VM it takes max(demand, CPU reservation) and adds the kernel CPU reservation. That is the capacity model Demand = Max(Utilization,Reservation).

With 9 VMs and ~15% Usage the host has plenty of free threads. VCF Operations 38% is flat reservation capacity, not work waiting to run. vCenter ~11% is the VMs’ actual scheduler demand, consistent with low Usage. Unmet demand would show as VM CPU Ready/Co-stop and rising Core/Thread Utilization, not as a Demand-Usage gap.

Check next: ESXi Thread Utilization and Core Utilization for headroom, and per-VM CPU Ready/Co-stop peak 20-second. If Core Utilization <100% and Thread Utilization <~80-90% with no VM contention, the host can take more VMs.
