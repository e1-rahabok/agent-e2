Quick answer · host esx-07
This host is quiet, with few VMs. The two attached charts show the same host over the same hour: the first from VCF Operations (CPU|Demand and CPU|Usage), the second from the vCenter performance chart (Demand and Usage in MHz). My manager reads the VCF Operations chart as unmet demand and asks for another host in the cluster. Is that right? Why do the two tools show different Demand for the same host?
📎 2 screenshots attached
Agent E2

No. VCF Operations CPU|Demand is not unmet demand; on a quiet host the gap to CPU|Usage is reserved capacity, not a wait.

Mechanism: VCF Operations CPU|Demand follows the capacity model: per running VM the higher of its demand and its CPU reservation, plus the kernel’s System Resource Reservation. vCenter cpu.demand is the scheduler sum-of-consumers view: ideal VM demand with no contention, reservations excluded. ESXi CPU Reserved Capacity is the VM reservations only; it excludes the kernel reservation that VCF Operations adds. vCenter Usage matches VCF Operations Usage in magnitude; the two Demand values differ because vCenter Demand omits VM and kernel reservations while VCF Operations includes them.

Reason: the host is quiet with few VMs, so real work is low and Usage ~300-480 MHz in VCF Operations and ~342 MHz average in vCenter. VCF Operations Demand ~2.9 GHz is the reserved capacity floor, not a shortfall. A reservation acts only under contention; unused reserved CPU is used by other VMs. Demand above Usage can be reservation alone. Performance is decided by VM CPU Ready/Co-stop, not by the Demand-Usage gap.
