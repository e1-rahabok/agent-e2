## Corrections

- A VM is just the virtual motherboard layer. A VM does not include the Guest OS running above the motherboard. Guest OS is a separate layer. A counter belongs to the layer that produces it, not to the object that stores it. See [`vsphere/architecture/vm-vs-guest-os`](vsphere/architecture/vm-vs-guest-os.md).
- Metrics with identical name, but on different objects, may not have the same meaning. For example, Linux CPU Usage, VM CPU Usage and ESXi CPU Usage differ in formula and meaning. Check the `same_name` links before answering. See [`vsphere/technology/cpu/metrics/virtual-motherboard/usage`](vsphere/technology/cpu/metrics/virtual-motherboard/usage.md).
- ESXi CPU Utilization, read per thread, is the metric for ESXi capacity, not ESXi Core Utilization, nor ESXi CPU Usage. See [`vsphere/technology/cpu/metrics/host/utilization`](vsphere/technology/cpu/metrics/host/utilization.md).
- Saturation is simply high utilization. It is not a peer to utilization. High utilization may lead to contention but not always, so saturation and contention are two different metrics. A performance problem happens only when contention happens. See [`vsphere/object-types/cluster/concepts/cluster-utilization-vs-contention`](vsphere/object-types/cluster/concepts/cluster-utilization-vs-contention.md).
- Provider and consumer see from different perspectives. ESXi supplies, the VM consumes; CPU Ready applies to the VM, never to ESXi. A value at the provider is just an aggregate of its consumers. See [`vsphere/architecture/provider-consumer`](vsphere/architecture/provider-consumer.md).
- CPU Latency is not always a problem: lower frequency raises it without any actual contention. Memory Latency and Disk Latency do mean the VM waits. See [`vsphere/technology/cpu/metrics/virtual-motherboard/latency`](vsphere/technology/cpu/metrics/virtual-motherboard/latency.md).
- High CPU Used or Usage but low CPU Run is not a reason to add vCPUs. See [`vsphere/technology/cpu/troubleshooting/run-vs-used-gap`](vsphere/technology/cpu/troubleshooting/run-vs-used-gap.md).
- Memory is a cache: Consumed stays high once pages are touched; that is normal and is not demand. Active is not a capacity counter. Size a Guest OS from Guest OS counters. See [`sp5-framework/capacity/rightsizing`](sp5-framework/capacity/rightsizing.md).
- Ballooned, Zipped, Swapped are past tense. Above 0 does not mean pressure now; memory contention decides. See [`vsphere/technology/memory/metrics/virtual-motherboard/ballooned`](vsphere/technology/memory/metrics/virtual-motherboard/ballooned.md).
- A threshold holds only for its object, its level within the object, and its sample interval. A 5-minute average hides 20-second peaks. See [`vcf-operations/features/peak-20-second-metrics`](vcf-operations/features/peak-20-second-metrics.md).
- vSphere Cluster Admission control counts reservations, not usage. A host at low usage can refuse a power-on. See [`vsphere/object-types/cluster/concepts/admission-control-and-cluster-state`](vsphere/object-types/cluster/concepts/admission-control-and-cluster-state.md).
- CPU overcommit ratios are per thread, not per core. A vCPU runs on a physical thread; 3:1 per thread is 6:1 per core. See [`sp5-framework/capacity/class-of-service-planning`](sp5-framework/capacity/class-of-service-planning.md).
