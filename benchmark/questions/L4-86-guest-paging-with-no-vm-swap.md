# Windows paging while vSphere shows no memory problem

## Prompt
- APP-07 is a Microsoft Windows Server 2022 VM with 8 GB, running a Java application server.
- Users say the application freezes for seconds at a time between 14:00 and 14:40.
- [The attached Performance Monitor log](0265/perfmon-app-07-memory.csv) covers 13:30-15:00 in 1-minute samples.
- vCenter, same window: VM Ballooned 0, Swapped 0, Swap in rate 0, Memory Latency 0%; Consumed flat at 8 GB; virtual disk latency 1-3 ms.
- The ESXi host has 40% of its memory free.
- The vSphere team says memory is fine: no ballooning, no swapping, no latency. They suggest the storage team look at the high disk queue.

Is the vSphere team right? Which layer is short of what, and what do you change?

## Likely wrong answer
"vSphere shows no ballooning, swapping or memory latency, so memory is fine; the disk queue points at storage."

## Expected key points
- No: Windows is short of memory in the 14:00-14:40 window, even though the VM is not.
- Evidence in the log: Available drops to about 110-190 MB, page-in and page-out are both high (thousands and hundreds per second), % Committed Bytes In Use rises above 90%, and the disk queue rises at the same time. Paging with a high disk queue is a memory shortage; outside the window all of it is quiet.
- The disk queue is caused by the paging, not by a slow datastore.
- The VM counters are right too: ESXi gives the VM all of its 8 GB from free host memory, so there is nothing to balloon, swap or wait for. VM memory counters measure ESXi's reclamation, not a shortage inside Windows.
- Fix inside the VM: give the VM more memory, or lower the Java heap and other memory the application takes, so Windows stops paging. Size from the Guest OS counters, not from VM Consumed.
- Check what runs at 14:00 (a job or a load peak) to size for that peak.

## Notes
- CSV generated by a seeded script. 14:00-14:40: Available MBytes 110-190, Pages Input/sec 1,800-4,200, Pages Output/sec 700-1,600, % Committed Bytes In Use 93-97, Avg. Disk Queue Length 6-14. Other minutes: Available 900-1,300 MB, Pages Input/sec below 80, disk queue below 0.8.
