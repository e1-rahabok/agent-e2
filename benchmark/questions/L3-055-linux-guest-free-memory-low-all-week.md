# Linux guest free memory low all week

## Prompt
- Four Linux VMs, web-arc-01 to web-arc-04, run nginx and serve a static file archive for a web site.
- A new monitoring rule on guest free memory has fired every day this week on web-arc-02. The ticket it opened asks to double the VM's memory.
- You export [the VCF Operations list of the four VMs](0387/vcf-operations-web-vms-memory-7-days.csv), last 7 days, and run three commands on web-arc-02:

```text
$ uptime
 10:42:53 up 12 days,  5:39,  1 user,  load average: 0.50, 0.27, 0.50
$ grep -E '^(pswpin|pswpout) ' /proc/vmstat
pswpin 0
pswpout 0
$ cat /proc/pressure/memory
some avg10=0.00 avg60=0.00 avg300=0.00 total=2313602
full avg10=0.00 avg60=0.00 avg300=0.00 total=1122752
```

Which statements are correct?

- A. Free memory this low for a week means Linux has no memory left for its applications.
- B. Linux keeps file data as page cache in memory its applications leave unused, and hands it back on demand.
- C. Linux has not swapped a page in or out since it last booted.
- D. The pressure stall information shows tasks stalled on memory in the last five minutes.
- E. Guest Needed Memory stays below half of the VM's memory at every point of the week.
- F. Double the VM's memory, as the ticket asks.
- G. Cut the VM to its current Needed Memory now, since the rest of its memory holds nothing of use.
- H. Linux counts the page cache it holds in MemFree.
- I. Guest Needed Memory, not guest free memory, is the input for the VM's memory size.

## Likely wrong answer
A: "Free memory near 0 for a week, so Linux is out of memory: add memory." Or D: the non-zero `total=` read as a current stall.

## Expected key points
- Answer: B, C, E, I.
- A false: Linux fills free memory with page cache. Read the memory available to applications (MemAvailable), swap activity and memory pressure, not free memory.
- B true: page cache is given back to applications on demand; free memory near 0 with healthy other counters means no waste.
- C true: reading. `pswpin` and `pswpout` count pages swapped in and out since boot; both are 0 and `uptime` shows more than a week since boot.
- D false: reading. `avg10`, `avg60` and `avg300` are 0.00 on both the `some` and the `full` line: no task stalled on memory in the last 10 seconds, minute or five minutes. `total=` is the stall time in microseconds since boot, not a current value.
- E true: reading. The row of web-arc-02 has `Guest|Needed Memory (KB) (Max)` below half of `Memory|Total Capacity (KB) (Last)` (the highest 5-minute value of the week).
- F false: the wrong action. Nothing shows a shortage; added memory would fill with more page cache and free memory would stay low.
- G false: over-correction. The page cache is in use: nginx serves files from it. The new size is the peak of Needed Memory over the business cycle plus headroom, cut in steps with a check after each.
- H false: MemFree excludes the page cache; that is why free memory is low while plenty is available.
- I true: Guest OS sizing uses Needed Memory as VMware Tools reports it, plus headroom; for memory, free is waste, not headroom.
