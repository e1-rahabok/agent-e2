# CPU Usage near 100%, a request for more vCPUs

## Prompt
- The owner of fin-rpt-05, a 4-vCPU VM with no CPU limit, asks for 2 more vCPUs: "VCF Operations shows the CPU maxed out every afternoon this week."
- Its host is lightly loaded and runs the Balanced power policy with Turbo Boost on.
- From VCF Operations: [the VM's daily CPU maximums for the last 7 days](0371/fin-rpt-05-cpu-daily-max-7-days.csv), and for yesterday afternoon [CPU|Usage (%)](0371/fin-rpt-05-cpu-usage-afternoon.csv) and [CPU|Net Run (%)](0371/fin-rpt-05-cpu-net-run-afternoon.csv).

Which statements are correct?

- A. Usage (%) above Net Run comes from Turbo Boost: Usage counts cycles against the base clock.
- B. Usage at or above 100% shows the vCPUs ran without a pause at those hours.
- C. Net Run is the share of time the vCPUs ran, less the time the kernel interrupted them.
- D. For sizing the guest's vCPUs, Net Run is a better input than Usage.
- E. CPU Demand is the counter to size on, since it adds the CPU the VM asked for and did not get.
- F. Usage has no use once Net Run is available: drop it from the VM's views.
- G. Ready and Co-stop stay low in the export: the vCPUs were rarely held back.
- H. Add the 2 vCPUs: the VM runs at its limit every afternoon.
- I. Net Run can pass 100% with Turbo Boost, just as Usage does.
- J. Before any change to the vCPU count, check the guest's CPU run queue at the busy hours.
- K. In the exports, Net Run reaches 100% at the afternoon peaks.
- L. At the afternoon peaks, Usage sits 20 points or more above Net Run.

## Answers
A, C, D, G, J, L

## Explanation
- A true: Usage (MHz and %) counts cycles completed, against the base clock; Turbo pushes it above the time-based counters. On a lightly loaded host the Hyper-Threading charge does not pull it down, so the gap is frequency.
- B false: the misconception. Net Run peaks at 72-82%: the vCPUs were idle a fifth to a quarter of the time while Usage read 100% or more.
- C true: Net Run = Run - Overlap; it counts time, not speed.
- D true: the guest is sized in vCPUs of run time; Usage moves with frequency and Hyper-Threading.
- E false: Demand is an internal counter of the scheduler and moves with the clock speed like Usage (its daily maximums track Usage, above Net Run); it is not unmet demand (under a limit it equals Usage) and not the guest's need.
- F false: over-correction. Usage is the throughput counter: the one to read for speed, not for sizing.
- G true: reading. In the daily file CPU|Ready (%) (Max) stays below 1 and CPU|Co-stop (%) (Max) below 0.5 on every day: the vCPUs were rarely held back.
- H false: wrong action. The vCPUs have idle time left; the extra points of Usage are clock speed.
- I false: Net Run is time-based and cannot pass 100%.
- J true: the guest run queue is the primary sign that the guest cannot keep up; it decides whether more vCPUs help.
- K false: reading. CPU|Net Run (%) peaks at 72-82%, in the afternoon file and in every day's maximum.
- L true: reading. In the afternoon files every 5-minute point with Usage at or above 100 has Net Run 20 points or more below it; each day's Usage maximum is 20 points or more above that day's Net Run maximum, from the same 5-minute point.
- Misconception: B or H: Usage at about 100% means the VM is at its limit, so add vCPUs.

## Reasoning path
1. Compare Usage with Net Run at the peaks: the gap is frequency.
2. Read Ready and Co-stop: no wait.
3. Size on Net Run and the guest run queue, not on Usage.
