# Windows free memory alert on a file server

## Prompt
- FS-03 is a Windows Server 2022 file server VM with 16 GB (16,384 MB).
- The monitoring tool raises "Memory Free below 300 MB" on it every day, all day.
- [The attached Performance Monitor log](0264/perfmon-fs-03-memory-24h.csv) covers yesterday in 30-minute samples.
- vCenter, same day: VM Consumed memory flat at 16 GB; VM Active memory 2.4-4 GB; Ballooned and Swapped 0.
- The operations team asks for 8 GB more memory.

Which statements are correct?

- A. Free is low because Windows keeps file data as standby cache; Available stays at 8,900-9,700 MB.
- B. Pages Input/sec stays low and the disk queue stays below 1: Windows does not wait on paging.
- C. % Committed Bytes In Use stays near 45%: committed memory is far from the commit limit.
- D. VM Consumed at 16 GB only shows that the guest has touched all its memory; it does not show what Windows needs now.
- E. VM Active at about 3 GB is what Windows needs, so the VM can shrink to 4 GB.
- F. The alert is right: free memory below 300 MB means Windows is about to page.
- G. Adding 8 GB will clear the alert for good, because Free will then stay above 300 MB.

## Likely wrong answer
F: low Free read as a shortage. Or E: VM Active used to size the guest.

## Expected key points
- Answer: A, B, C, D.
- A is correct: Available = Standby + Free, ready for use at once. Standby holds cached file pages that Windows hands out at once; low Free with high Standby is normal and means no waste.
- B is correct: page-in is low all day and the disk queue is low; paging together with a high disk queue is the sign of a shortage, and it is absent.
- C is correct: committed virtual memory is under half of the commit limit.
- D is correct: Consumed counts pages the guest touched since boot and ESXi still backs. Windows frees pages in its own lists without telling ESXi.
- E is wrong: Active is a VM counter, a sample of recently touched pages. Sizing reads the Guest OS counters, cache included; 4 GB would remove the file cache this server works from.
- F is wrong: the alert reads the wrong counter. Watch Available, paging with the disk queue, and % Committed.
- G is wrong: Windows fills added memory with more standby cache, so Free stays low and the alert keeps firing.
