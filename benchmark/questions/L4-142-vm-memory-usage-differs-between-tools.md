# VM Memory Usage differs between vCenter and VCF Operations

## Prompt
- A Windows Server VM with 24 GB of memory and VMware Tools running.
- The owner's capacity report, from VCF Operations, shows the VM's memory usage far higher than the vCenter chart the vSphere team reads. The owner asks which tool is wrong.
- The vSphere team proposes to cut the VM's memory to what vCenter shows it uses.
- The vCenter keeps statistics level 2 for all intervals. Both exports cover the same 12 hours of yesterday: [the vCenter memory export](0395/vcenter-vm-memory-12h.csv) (Usage in %, the other columns in KB) and [the VCF Operations list view export](0395/vcf-operations-vm-memory-12h.csv).

Which statements are correct?

- A. In the vCenter export, Usage moves with Active, not with Consumed.
- B. Needed Memory over Total Capacity matches VCF Operations Memory|Usage (%) within about two points.
- C. Consumed in the vCenter export sits below half of the VM's memory.
- D. The two Usage metrics read so differently that one of the tools must be reporting wrongly.
- E. VCF Operations shows the higher value because it turns 20-second samples into 5-minute averages.
- F. ESXi did not make the VM wait for memory at any point of the 12 hours.
- G. Shrink the VM to about the Active value in the vCenter export.
- H. Memory Contention plays no part in the new size: it measures time spent waiting, not memory space.
- I. Consumed close to the VM's memory shows that Windows is using all of it.
- J. Both Usage metrics are built from ESXi counters, so neither says what Windows needs.

## Likely wrong answer
D: "The same counter cannot read so differently on the same day: one tool is wrong." Or G: Active taken as what Windows uses.

## Expected key points
- Answer: A, B, F, H.
- A true: in every row, `Usage for erp-db-11` is within 2 points of `Active for erp-db-11` / 25,165,824 KB × 100 (between 7% and 15%) and moves with it, while `Consumed for erp-db-11` stays high and flat.
- B true: the Max, Min, First and Last of `Guest|Needed Memory (KB)` over `Memory|Total Capacity (KB)` each match the same column of `Memory|Usage (%)` within two points: VCF Operations VM Memory Usage (%) = Guest OS Needed Memory / VM Memory Total Capacity × 100.
- C false: `Consumed for erp-db-11` is at 85% or more of the 24 GB in every row.
- D false: one name, two formulas. Both tools report correctly; they read different layers.
- E false: the vCenter export also holds 5-minute rows, and averaging cannot turn Active into Needed Memory.
- F true: Memory Contention, the share of time a vCPU waits on page faults ESXi resolves, has a Max of 0 over the 12 hours.
- G false: the wrong action. Active is a sampled kernel estimate of recently touched pages; a cut to it removes the cache Windows works from.
- H true: Guest OS sizing leaves memory contention out of the size, because contention is speed and sizing is space; contention counts only in choosing which VMs can give memory back (a VM that already waits gives none).
- I false: Consumed counts pages the VM has touched since power-on and ESXi still backs; it is not what Windows uses now.
- J false: over-correction. VCF Operations Usage (%) reads Guest Needed Memory, which VMware Tools collects inside the guest.
