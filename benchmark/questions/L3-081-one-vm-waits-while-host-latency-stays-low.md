# One VM waits for memory while the host latency stays low

## Prompt
- Users of an application report that it was slow for about half an hour yesterday.
- The application runs on VM ord-api-03. Its host, esx-c22, ran 24 powered-on VMs all day.
- The host team checks the host's memory Latency, sees it low all day, and wants to close the ticket as not a memory problem.
- The vCenter keeps statistics level 2 for all intervals. Exports of 00:00-12:00 UTC yesterday: [the host memory export](0403/vcenter-host-memory-12h.csv) (Latency and Usage in %) and [the VM memory export](0403/vcenter-vm-memory-12h.csv) (Latency in %, Swap in rate in KBps).

Which statements are correct?

- A. Host Latency dilutes one VM's wait across all the VMs running on the host.
- B. The host's low Latency values show that every VM on the host got the memory it touched without waiting.
- C. The VM's Latency shows its vCPUs stalled on page faults 5% or more of the time for about half an hour.
- D. Host Latency rises above 1% in the same half hour as the VM's Latency peaks.
- E. Host Latency would react only if all of the host's VMs waited together.
- F. Mark the ticket as not a memory issue on the strength of the host export.
- G. To find who waited, rank the host's VMs by their own memory Latency or Memory Contention.
- H. The VM's peak value is the part of its memory that ESXi had put on disk.

## Answers
A, C, G

## Explanation
- A true: host memory Latency is a normalized average of the running VMs' Latency; one VM's wait among 24 is diluted: `Latency for esx-c22` rises only slightly in the rows where `Latency for ord-api-03` peaks, and stays at 0.5% or less.
- B false: the average hides the VM that suffers: `Latency for ord-api-03` reaches 5% or more while the host stays low.
- C true: `Latency for ord-api-03` is between 5% and 10% in six consecutive 5-minute rows (30 minutes) and 0 in every other row: its vCPUs waited for page faults ESXi resolves, mostly swap-in (`Swap in rate for ord-api-03` is above 0 in the same rows).
- D false: `Latency for esx-c22` is at 0.5% or less in every row, the peak rows included.
- E false: over-correction. Any VM's wait adds to the average; one VM among many moves it only a little.
- F false: the wrong action from B. The VM waited on memory in the window the users report.
- G true: the worst VM decides; read the maximum VM memory Latency (VCF Operations Memory Contention) across the host's VMs.
- H false: Latency is a share of time, not of memory space.
- Misconception: B: "The host's memory latency stayed low, so no VM waited: not a memory problem."
