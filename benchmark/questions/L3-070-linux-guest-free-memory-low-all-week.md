# Linux guest free memory low all week

## Prompt
- Four Linux VMs, web-arc-01 to web-arc-04, run nginx and serve a static file archive for a web site.
- A new monitoring rule on guest free memory has fired every day this week on web-arc-02. The ticket it opened asks to double the VM's memory.
- You export [the VCF Operations list of the four VMs](0387/vcf-operations-web-vms-memory-7-days.csv), last 7 days, and run three commands on web-arc-02:

```text
$ uptime
 10:42:53 up 12 days,  5:39,  1 user,  load average: 0.50, 0.27, 0.50
$ vmstat 5 3
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 0  0      0 440992 300787 10637425    0    0    40    33  394 1282  2  2 96  0  0
 0  0      0 417798 300928 10660478    0    0   100    39  362  706  1  1 98  0  0
 1  0      0 419736 301024 10658444    0    0   125    11  593  656  2  2 96  0  0
$ cat /proc/pressure/memory
some avg10=0.00 avg60=0.00 avg300=0.00 total=2313602
full avg10=0.00 avg60=0.00 avg300=0.00 total=1122752
```

Which statements are correct?

- A. Free memory this low for a week means Linux has no memory left for its applications.
- B. Linux fills unused memory with page cache and hands it back to applications on demand.
- C. vmstat shows no swap-in and no swap-out on web-arc-02 while it ran.
- D. VCF Operations can chart web-arc-02's memory pressure stall share next to Guest Needed Memory.
- E. Guest Needed Memory stays below half of the VM's memory at every point of the week.
- F. Doubling the VM's memory would stop the free memory alerts.
- G. Its current Needed Memory, with no headroom, is the right new size for web-arc-02.
- H. Linux counts the page cache it holds in MemFree.
- I. Memory that Linux leaves free is waste, not safe headroom.

## Answers
B, C, E, I

## Explanation
- A false: Linux fills free memory with page cache. Read the memory available to applications (MemAvailable), swap activity and memory pressure, not free memory.
- B true: page cache is given back to applications on demand; free memory near 0 with healthy other counters means no waste.
- C true: reading. `si` and `so` are the swap-in and swap-out columns of vmstat; both are 0 in every line, and `swpd` is 0.
- D false: `/proc/pressure/memory` gives the share of time tasks stalled on memory, but VMware Tools does not collect it, so VCF Operations does not show it; it is read inside Linux, as here.
- E true: reading. The row of web-arc-02 has `Guest|Needed Memory (KB) (Max)` below half of `Memory|Total Capacity (KB) (Last)` (the highest 5-minute value of the week).
- F false: nothing shows a shortage, and added memory would fill with more page cache, so free memory would stay low and the alerts would go on.
- G false: over-correction. The page cache is in use: nginx serves files from it. The new size is the peak of Needed Memory plus headroom, so the result lands in the green band, not at 100%; a cut goes in steps with a check after each.
- H false: MemFree excludes the page cache; that is why free memory is low while plenty is available.
- I true: memory is cache, and unused memory is waste; free memory is not safe headroom. Guest OS sizing uses Needed Memory as VMware Tools reports it, plus headroom.
- Misconception: A: "Free memory near 0 for a week, so Linux is out of memory: add memory." Or F: more memory taken to stop the free memory alerts.
