# CPU Wait fills the export of a quiet VM

## Prompt
- A monitoring tool flags svc-int-08, an 8-vCPU VM: "CPU Wait critical." The service desk asks whether the VM is starved of CPU and should get more vCPUs.
- The VM runs on an ESXi 9.1 host.
- You export the VM's CPU from vCenter, Real-time: [the attached vCenter export](0372/svc-int-08-cpu-real-time.csv).

Which statements are correct?

- A. Most of the Wait in the export is Idle: the guest had halted its vCPUs for lack of work.
- B. The export shows the VM waiting for physical CPU most of the time.
- C. Each 20-second sample of the export adds up to about 160,000 ms across Run, Ready, Co-stop and Wait.
- D. On average, a vCPU spent about 90% of the time in Wait.
- E. Wait minus Idle, the part made of Swap Wait and Other Wait, stays under 1,000 ms in the export.
- F. Ready in the export is above 5,000 ms in most samples.
- G. Wait holds nothing but idle time, so stalls on IO or swapped memory can never appear in it.
- H. Add vCPUs so that each one waits less.
- I. A halted vCPU stays parked on its physical thread until the guest wakes it.
- J. Whether the VM is held back is read from Ready and Co-stop, which stay low here.

## Likely wrong answer
B or H: Wait near its maximum means the VM waits for CPU, so give it more vCPUs.

## Expected key points
- Answer: A, C, D, E, J.
- A true: in every row `Idle for svc-int-08` is within 1,000 ms of `Wait for svc-int-08`. A halted vCPU is de-scheduled and counted in Wait.
- B false: the misconception. Waiting for a physical thread is Ready, which stays below 800 ms; Wait is mostly the guest's own idle time.
- C true: per vCPU, Run + Ready + Co-stop + Wait = 20,000 ms per sample; the VM value sums eight vCPUs, and every row adds up to 160,000 ms.
- D true: Wait of 140,000-150,000 of 160,000 ms is about 88-94% per vCPU on average.
- E true: Wait - Idle = Swap Wait + Other Wait, under 1,000 ms in every row (Swap wait reads 0).
- F false: reading. Ready stays below 800 ms in every sample.
- G false: over-correction. Wait = Idle + Swap Wait + Other Wait; IO and swap stalls show in its non-idle part.
- H false: wrong action. The vCPUs are idle, not waiting for threads; more vCPUs add idle vCPUs and make the VM harder to schedule.
- I false: a halted vCPU is de-scheduled and holds no physical thread; other VMs can run there.
- J true: Ready and Co-stop are the waits for the hypervisor; Ready stays below 800 ms and Co-stop near 0 of 160,000 ms.

## Reasoning path
1. Compare Wait with Idle: nearly equal.
2. Add the states: 160,000 ms per sample for 8 vCPUs.
3. Ready and Co-stop near 0: the VM is quiet, not starved.
